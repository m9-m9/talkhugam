# Mux 실제 재생 오류 복구 계획

**목표:** 재생 권한 조회가 성공했더라도 Mux 미디어가 재생되지 않는 경우를 별도 상태로 안내하고, 사용자가 대화나 영상 기록을 잃지 않은 채 다시 시도할 수 있게 한다.

## 배경

1. 기존 흐름은 영상 정보와 재생 권한 조회 실패만 화면에 안내했다.
2. Mux Player가 실제 스트림·토큰 오류를 내면 사용자에게 재시도 경로가 없었다.
3. E2E는 형식만 맞는 가짜 재생 토큰으로 실제 Mux에 접속해 브라우저 콘솔 오류를 만들고 있었다.

## 구현 범위

1. 공통 Mux Player가 `onError` 이벤트를 화면용 `onPlaybackError` 콜백으로 전달한다.
2. 영상 상세 화면은 미디어 재생 실패를 재생 권한 조회 실패와 구분해 안내하고, `재생 다시 시도`와 `영상 기록으로 가기`를 제공한다.
3. 책 대화의 영상 메시지는 해당 카드만 오류·재시도 상태로 전환해 대화 타임라인을 유지한다.
4. E2E에서는 가짜 성공 토큰으로 실제 Mux 스트림을 열지 않고, 권한 실패 응답과 사용자 복구 흐름을 검증한다.

## 완료 기준

- Mux `onError`가 발생하면 상세 화면과 책 대화 카드가 각각 오류 안내를 표시한다.
- 재시도는 해당 영상의 재생 권한만 다시 요청한다.
- 책 대화의 제목과 다른 메시지는 영상 재생 실패 뒤에도 유지된다.
- E2E가 유효하지 않은 Mux 토큰으로 외부 스트림을 요청하지 않는다.
- 단위·페이지·E2E·lint·typecheck·build 검증을 통과한다.
