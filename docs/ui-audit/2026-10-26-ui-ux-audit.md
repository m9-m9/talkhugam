# Talk후감 UI/UX 전체 점검 (2026-10-26)

`design.md`의 「외부 가이드 반영 기준」(UI UX Pro Max `d14efff`, Taste Skill `12af471`)과 기존 체크리스트로 웹 앱 전체를 점검한 결과다.

## 점검 방법

- **화면**: `pnpm --filter @talkhugam/web exec playwright test e2e/ui-health.spec.ts`로 320px·640px 스크린샷 44장을 다시 찍고 직접 봤다(`apps/web/artifacts/seed-comparison/`). 100개 테스트 모두 통과했고 axe 접근성 검사도 통과했다.
- **코드**: `apps/web/src` 화면 파일(`*.tsx` 57개, 테스트 제외)과 `globals.css`에서 패턴 수를 셌다.
- **보지 못한 범위**: 로그인·온보딩·법적 문서·운영자 화면은 스크린샷이 없어 코드로만 봤다. 실제 iOS Safari(safe-area, 키보드)와 화면 낭독기 테스트는 하지 않았다.

## P0 — 디자인 기준 문서와 실제 화면이 다름

`design.md` 팔레트는 **흰 바탕 + `#111111` 글자 + 코랄 `#FF6F4D`**인데, 실제 토큰(`apps/web/src/shared/styles/globals.css:25-41`)은 **검정 바탕 `#000000` + 흰 글자 + brand `#ff835f` / action `#ad3d22`**이다. e2e 테스트도 다크 테마를 기준으로 검증한다("dark sign-in screen", "dark SEED information fields").

- 문서를 기준으로 점검하면 모든 화면이 "틀렸다"고 나와서 점검 기준으로 쓸 수 없다.
- **결정 필요**: 다크 테마가 현재 기준이면 `design.md` 팔레트 표와 「대화 화면 규칙」(내 말풍선 black, 상대 white)을 다크 기준으로 고쳐야 한다. 라이트가 목표면 토큰과 e2e 기대값을 다시 바꿔야 한다.

## P1

### 1. 코랄이 화면마다 3곳 이상

기준: 한 화면에서 넓은 코랄 면 1개, 코랄 신호 1-2곳.

| 화면 (320px)     | 코랄이 쓰인 곳                                                                    |
| ---------------- | --------------------------------------------------------------------------------- |
| 책방 만들기      | 주요 CTA, 중앙 FAB `+`, 피드백 버튼 → 넓은 코랄 면 3개                            |
| 계정 설정        | eyebrow "계정", 스위치 3개, FAB, 피드백 버튼                                      |
| 영상 기록        | 필터 칩 3개(선택 채움 + 나머지 코랄 테두리), "영상 추가" 테두리, FAB, 피드백 버튼 |
| 책 대화          | eyebrow, 선택된 "영상" 탭 채움, 전송 버튼                                         |
| 메시지 추가 시트 | 버튼 6개 모두 코랄 테두리·코랄 글자                                               |

원인은 공용 클래스다. `talkhugam-foundation-toggle`, `talkhugam-action-sheet-choice`, `talkhugam-foundation-action--outline`(`globals.css:79-134`)이 기본 상태부터 코랄 테두리와 `--color-accent-text`를 쓴다. 이 세 클래스를 회색 테두리 + 흰 글자로 바꾸고 선택 상태만 표시하면 대부분 화면이 한 번에 정리된다.

### 2. 피드백 버튼이 본문을 가림

`FeedbackLauncher`(`apps/web/src/features/feedback/FeedbackLauncher.tsx:76`, 위치 `globals.css:432-441`)가 하단 내비게이션 위 오른쪽에 떠 있다.

- 320px 책방 목록: 빈 상태 문장 "책방을 만들거나 초대 코드로 참여해 보세요"의 끝을 가린다.
- 320px 내 정보: "서비스 정보" 설명의 끝을 가린다.
- 중앙 FAB `+`와 같은 높이에 큰 코랄 원형 버튼이 두 개 떠 있어 무엇이 주요 행동인지 흐려진다.

제안: 피드백은 내 정보 > 서비스 정보 같은 메뉴 행으로 옮기거나, 남겨 둘 거면 흑백 작은 버튼으로 낮추고 페이지 아래 여백에 버튼 높이만큼을 더한다.

### 3. 제목마다 붙은 eyebrow 라벨과 같은 말 반복

Taste Skill에서 금지하는 2세대 생성형 UI 티다. 게다가 header 제목과 같은 말을 반복한다.

- 계정 설정: header "계정 설정" → eyebrow "계정" → H1 "계정 설정" (`AccountSettingsPage.tsx:104`)
- 책방 상세: header "책방" → eyebrow "책방" → H1 "금요일 아침 책방"
- 책 대화: header "책방" → eyebrow "책 대화" → H1 (책 제목)
- 같은 패턴: `ProfileEditPage.tsx:132`, `ProfileSharePage.tsx:53`, `NaverAccountInfoPage.tsx:33`

제안: eyebrow를 지운다. 문맥이 꼭 필요하면 H1 아래 보조 문장에 넣는다.

### 4. "메시지 추가" 시트가 버튼 카드 격자

책 대화 `+` 메뉴가 코랄 테두리 박스 6개를 2열로 놓은 형태다. 제목 아래 가운데 "닫기" 버튼이 따로 떠 있어서 위계도 애매하다. 이미 import한 SEED `menu-sheet` / `menu-sheet-item` recipe로 아이콘 + 라벨 목록 행을 만들고, 닫기는 시트 헤더 오른쪽 아이콘 버튼이나 바깥 탭으로 처리하는 편이 기준에 맞다.

### 5. 오류 상태에 회복 행동이 없음

책 대화 영상 탭의 "영상 처리를 완료하지 못했어요. 잠시 후 다시 시도해 주세요."(`BookDiscussionPage.tsx:1494`)는 다시 시도할 버튼이 없다. 같은 스크린샷에서 H1은 "책을 불러오고 있어요."라서 로딩과 오류가 한 화면에 같이 나온다. `RetryState`를 쓰거나 해당 영상 카드 안에 `다시 시도`·`삭제`를 둔다.

## P2

1. **하단 내비게이션 라벨에 아이콘 없음** — "책방", "내 정보" 글자만 있고 중앙 `+`에는 라벨이 없다(`AppBottomNavigation.tsx:15-16`). 내비게이션 항목에 아이콘 + 라벨을 두고, 현재 위치를 굵기 말고도 표시한다.
2. **스위치 행 끝이 들쭉날쭉** — 계정 설정의 스위치가 라벨 바로 뒤에 붙는다(`AccountSettingsPage.tsx:318-324`). 라벨은 왼쪽, 스위치는 오른쪽 끝에 맞춘다.
3. **보관·나가기 행동이 코랄** — 방 관리 확인 다이얼로그의 "보관하고 나가기"가 주요 행동과 같은 코랄이다. danger token(`--color-danger`)과 분리된 위치를 쓴다. 다이얼로그 뒤쪽 "방 설정"·"방 보관하고 나가기" 버튼은 비활성처럼 보일 만큼 대비가 낮아 측정이 필요하다.
4. **특수 기호를 아이콘으로 사용** — `✦`(`InviteShareSheet.tsx:88`, `JoinRoomPage.tsx:56`), `★`(`CompletionReviewForm.tsx:69`, `BookDiscussionPage.tsx:618`). 별점의 `aria-label`이 `<p>`에 있어 낭독기에서 안 읽힐 수 있다. SVG 아이콘 + 화면에 보이는 "5점" 텍스트로 바꾼다.
5. **`100vh`/`min-h-screen` 25곳, `dvh` 6곳** — `AppShell.tsx:5`, `AuthenticatedRoute.tsx:49`, `globals.css:303,339,423,428` 등. 모바일 주소창 때문에 높이가 넘친다. `min-h-dvh`로 통일한다.
6. **safe-area 처리 0곳** — 하단 내비게이션, composer, 시트가 `env(safe-area-inset-bottom)`을 쓰지 않고 viewport meta에 `viewport-fit=cover`도 없다. 홈 화면에 추가한 iOS 환경에서 확인이 필요하다.
7. **이미지가 자리를 미리 잡지 않음** — `<img>` 7곳 중 `width`/`height`나 `loading="lazy"`가 있는 곳이 없다. 640px 책방 목록 스크린샷에서 헤더 워드마크(`RoomsPage.tsx:42`)가 비어 찍힌 것도 이미지 로드 타이밍 때문으로 보인다.
8. **숫자 폭 고정 없음** — `tabular-nums` 0곳. 캐러셀 `1 / 2`, "0명 완독", 영상 시간에 적용한다.

## P3

1. **640px에서 빈 공간** — 베스트셀러 작은 카드가 2개라 오른쪽 1/3이 비고, 빈 상태 아래에도 큰 빈 영역이 남는다. 카드 수에 맞춰 열 수를 정한다.
2. **굵기 남발** — `font-bold` 64회 / 27개 파일, `font-semibold` 51회. `RoomManagementPage.tsx` 6회, `InviteShareSheet.tsx` 5회. 화면당 1-2개 기준에 맞춰 줄인다.
3. **정렬선 어긋남** — 책방 만들기에서 필드 라벨이 입력창보다 약 2px 안쪽에서 시작하고, 안내 문구 "초대받은 사람만…"이 필드와 떨어져 CTA 쪽에 붙어 있다.
4. **아이콘 체계 없음** — `design.md`는 `lucide-react`를 권장하지만 의존성에 없고, 아이콘은 파일마다 직접 그린 SVG다. 피드백 아이콘은 `scale(1.75)`로 키운다(`globals.css:449-452`). 한 세트로 정해 크기 18-22px, 같은 stroke 두께로 맞춘다.

## 잘 되어 있는 것

- 100개 UI 테스트와 axe 검사 통과, 320px·640px 가로 넘침 없음
- `aria-label` 95곳, `aria-live`/`role="status"`/`role="alert"` 37곳
- 시트·다이얼로그의 Esc·바깥 클릭·포커스 복귀가 테스트로 보장됨
- 그라데이션(브랜드 로고 제외)·glass·blur·보라색 없음, 캐러셀 자동 전환 없음
- 캐러셀과 시트 모션에 `motion-reduce` 대응, 전역 reduced-motion 규칙 있음(`globals.css:840`)
- 빈 상태가 대부분 한 문장 + 한 행동 기준을 지킴

## 제안하는 작업 순서

1. P0 결정(다크/라이트) 후 `design.md` 팔레트 갱신
2. 공용 클래스 3개의 기본 코랄 제거 → P1-1 대부분 해결
3. eyebrow 제거, 피드백 버튼 위치 변경
4. 메시지 추가 시트를 목록형으로 변경, 영상 오류에 재시도 추가
5. P2를 묶어 하나의 접근성·모바일 PR로 처리
