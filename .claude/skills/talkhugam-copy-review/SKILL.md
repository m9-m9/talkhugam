# Talk후감 카피 리뷰

Talk후감은 "독서 경험을 함께 나눈다"는 브랜드로, 책방 안에서 책을 읽고 느낀 걸
나누는 앱이다. 이 스킬은 앱 안의 모든 사용자 대면 한국어 문구(버튼, 헤딩, 에러,
빈 상태, 로딩, aria-label, placeholder)를 이 브랜드 관점에서 검사한다.

토스의 8가지 라이팅 원칙(https://toss.tech/article/8-writing-principles-of-toss)을
뼈대로 삼되, 그대로 베끼지 않고 Talk후감의 정체성에 맞게 재해석했다. 원칙은 딱딱한
규칙이 아니라 "왜 이게 사용자에게 중요한가"를 판단하는 렌즈로 쓴다 — 기계적으로
적용하면 오히려 부자연스러운 문구가 나온다.

## 왜 이게 중요한가

책을 읽고 느낀 걸 나누는 행위는 감정적이고 사적인 경험이다. 앱의 문구가 사무적이거나
용어가 화면마다 다르면, 사용자는 "이게 내 책방인가 그냥 앱인가" 헷갈리게 되고
브랜드가 약속하는 "함께 나누는 경험"이 깨진다. 반대로 문구가 일관되고 감정을 살짝
얹으면, 기능은 그대로여도 훨씬 더 브랜드답게 느껴진다.

## 브랜드 원칙 (토스 8원칙 → Talk후감 재해석)

1. **다음을 예상하게 하기 (Predictable hint)** — 버튼을 누르면 뭐가 일어날지
   문구만 보고 알 수 있어야 한다. "확인"보다 "함께 읽기 시작하기"처럼 결과를 담는다.
2. **불필요한 단어 걷어내기 (Weed cutting)** — 의미 없는 수식어("정말", "그냥",
   "너무") 제거. 단, 완전히 건조하게 만들지 말고 감정 하나는 남긴다(아래 8번 참고).
3. **의미 없는 문장 제거 (Remove empty sentences)** — 정보량 없는 문장을 넣지
   않는다. 특히 placeholder나 subtext에 뻔한 말("여기에 입력하세요")을 넣지 않는다.
4. **핵심 메시지에 집중 (Focus on key message)** — 에러/빈 상태에서 원인 설명보다
   "지금 뭘 하면 되는지"를 먼저 말한다.
5. **말하듯 쉽게 (Easy to speak)** — 개발자 용어, 시스템 상태값을 그대로 노출하지
   않는다. "프론트엔드", "세션", "리소스" 같은 말은 사용자 문구에 등장하면 안 된다.
6. **강요보다 제안 (Suggest than force)** — "~해야 합니다", "실패했습니다" 같은
   책망조 대신 "~해 보세요", "~못했어요, 다시 시도해 주세요"처럼 부드럽게.
7. **누구나 이해하는 말 (Universal words)** — 특정 세대나 커뮤니티에서만 통하는
   신조어·줄임말을 피한다. 감탄사("앗", "살짝")도 한 화면에서만 튀지 않게 전체
   톤과 맞춘다 — 캐주얼하게 갈 거면 앱 전체가 캐주얼해야 하고, 아니면 절제한다.
8. **숨은 감정 찾기 (Find hidden emotion)** — 정보 전달에 그치지 않고, "함께 읽고
   느낀 걸 나눈다"는 감정을 문구 어딘가에 얹을 수 있는지 검토한다. 히어로 카피에만
   감정을 넣고 실제 버튼("전송", "저장하기")은 건조하게 두면 브랜드 목소리가
   화면 앞부분에서만 살고 끝난다 — CTA까지 톤을 끌고 가는 걸 우선 시도한다.

추가로 Talk후감만의 기본 규칙:
- 모든 문구는 **해요체**로 통일한다 (다른 종결어미가 섞이면 바로 지적한다).
- 에러 메시지는 "~하지 못했어요. 잠시 후 다시 시도해 주세요." 패턴을 기본으로 한다.
- 빈 상태는 "아직 ~없어요" 패턴을 기본으로 한다.
- 로딩 상태는 "~하고 있어요." 패턴을 기본으로 한다.

## 용어집 — 같은 개념은 하나의 단어로

Talk후감 코드베이스를 조사하며 실제로 화면마다 다른 단어가 섞여 쓰이는 걸 발견했다.
아래 표의 왼쪽이 표준 용어다. 오른쪽 단어가 사용자 대면 문구에 나오면 지적한다
(설명 문장 속 자연스러운 보조 표현은 허용하되, 제목/헤딩/버튼/필드 라벨처럼
사용자가 "이름"으로 인식하는 자리에는 반드시 표준 용어를 쓴다).

| 표준 용어 | 섞여 쓰이던 표현 | 근거 |
|---|---|---|
| 책방 | 독서방, 모임 | 사용자에게 보이는 공간명·탭·CTA·필드 라벨은 모두 책방으로 부른다. `reading_rooms`, `/rooms` 같은 기술 이름은 호환성을 위해 유지한다. |
| 책 대화 | 책 채팅방 | 과거에 화면과 코드에서 함께 쓰이던 표현이다. 모든 사용자 문구는 책 대화로 쓴다. |
| 독후감 | 감상 | 브랜드명 Talk후감의 핵심 개념이다. 라벨을 제외한 텍스트 기록의 표준 이름은 독후감이다. |
| 이름 | 닉네임 | 온보딩과 프로필 편집의 입력 필드는 이름으로 통일한다. |
| 로그인 관리 | 계정 관리 | 로그인 수단과 연결 계정을 다루는 설정 구역의 표준 이름이다. |

### 책방 용어 기준
사용자가 보는 공간의 공식 이름은 **책방**이다. `독서방`과 `모임`은 과거 표기이므로 제목,
탭, CTA, 입력 필드 라벨, 빈 상태, 오류 문구에서 발견하면 **책방**으로 바꾸도록 지적한다.
`모임`은 사람들의 활동을 부연하는 설명문에서만 제한적으로 허용한다.

새로운 용어 혼용을 발견하면 이 표에 추가해서 스킬을 업데이트한다.

## 알려진 안티패턴 (실사례)

이전 리뷰에서 발견된 것들. 같은 패턴이 다른 화면에도 있는지 항상 확인한다.

- **개발자 언어 노출**: `HomePage.tsx`의 `"Talk후감 프론트엔드 기반을 준비하고
  있어요."` — "프론트엔드"는 사용자가 절대 봐서는 안 되는 개발 용어. 스캐폴딩/
  플레이스홀더 문구가 실제 라우트에 남아있지 않은지 항상 확인한다.
- **감정 없는 CTA**: 히어로 카피("읽고 느낀 마음을 함께 나눠요")는 감성적인데
  실제 버튼("전송", "저장하기", "검색", "추가", "삭제")은 완전히 기능적인 언어로
  후퇴하는 패턴. 버튼 하나하나를 감성적으로 바꾸라는 게 아니라, 바꿀 수 있는
  자리(예: 완독 확인, 총평 저장처럼 감정이 실리는 액션)를 놓치지 않았는지 본다.
- **톤 스파이크**: `JoinRoomPage.tsx`의 "앗", "살짝" 같은 감탄사가 앱의 나머지
  화면(안정적인 해요체, 감탄사 없음)과 톤이 다르다. 캐주얼한 표현이 한 화면에만
  고립돼 있으면 의도된 것인지 실수인지 반드시 짚는다.
- **혼용 표기**: 위 용어집 참고.
- **에러 톤 이중 기준**: 앱 대부분의 에러는 "~하지 못했어요. 잠시 후 다시 시도해
  주세요." 패턴(부드러움)을 쓰는데, 영상/검색 관련 상태 메시지 일부는 "~에
  실패했어요"(더 단정적인 "실패" 표현)를 쓴다 — `BookDiscussionPage.tsx`/
  `VideoArchivePage.tsx`의 "영상 처리에 실패했어요.", `BookSearchPage.tsx`의
  "도서 검색에 실패했어요." 다른 에러 메시지와 같은 패턴으로 통일할지 검토한다.

## 검사 절차

1. **범위 확인**: 사용자가 특정 파일/화면을 지정했으면 그것만, 아니면
   `apps/web/src/pages`, `apps/web/src/features`, `apps/web/src/shared/ui`,
   `apps/web/src/entities`(zod validation 메시지 포함) 전체를 대상으로 한다.
2. **문구 수집**: JSX 텍스트, `placeholder=`, `aria-label=`, `title=`, 에러/토스트/
   빈 상태 문자열, validation 메시지를 grep으로 모은다. 코드 안 상수 파일
   (`copy.ts`, `messages.ts`)이 있으면 우선 확인 — 없으면 컴포넌트에 인라인.
3. **원칙별 대조**: 위 8원칙 + 용어집 + 안티패턴 목록에 하나씩 대조한다.
   특히 같은 개념(방, 책 대화, 완독 등)을 부르는 이름이 파일마다 다른지 교차 확인한다.
4. **심각도 분류**:
   - **높음**: 개발자 용어 노출, 사용자가 실제로 헷갈릴 용어 혼용
   - **중간**: 톤 일관성 문제 (감탄사 스파이크, CTA 톤 후퇴)
   - **낮음**: 스타일 다듬기 수준 (표현 하나 더 자연스럽게)

## 리포트 형식

파일 경로와 줄 번호를 반드시 포함해서, 심각도 순으로 정리한다:

```markdown
## 카피 리뷰 결과

### 높음
- **[문제 한 줄 요약]** — `path/to/File.tsx:줄번호`
  - 현재: "..."
  - 원칙: [위반한 원칙]
  - 제안: "..."

### 중간
...

### 낮음
...

### 잘 지켜지고 있는 부분
(있으면 짧게 언급 — 다음 리뷰에서 회귀했는지 비교하기 위함)
```

발견한 새로운 용어 혼용이나 안티패턴은 이 SKILL.md의 용어집/안티패턴 섹션에
바로 추가해서, 다음 리뷰부터 반복 발견하지 않도록 한다.
