# 계정 삭제 완료 기록 정합성 구현 계획

> **에이전트 작업 필수 절차:** 실패 테스트를 먼저 작성하고, 구현 뒤 독립 QA 검토와 함수·DB 검증을 진행한다.

**목표:** Auth 사용자 삭제가 성공한 뒤 완료 기록 요청이 일시적으로 실패해도 사용자에게 삭제 실패를 잘못 알리지 않고, 운영자가 복구할 수 있게 한다.

**구조:** Edge Function은 Auth 삭제 성공 여부를 별도로 보관한다. 완료 기록은 제한된 횟수만큼 재시도하고, 모두 실패하면 삭제 성공 응답과 `completionPending` 상태를 반환한다. DB 운영 상태에는 오래 남은 `prepared` 삭제 요청 수를 표시하고, 복구 절차는 Runbook에 기록한다.

**기술:** Supabase Edge Functions, PostgreSQL, Deno test, pgTAP

---

### 작업 1: 실패 경계 테스트

- [x] 완료 기록이 일시 실패 후 재시도에서 성공하는 순수 함수 테스트를 작성한다.
- [x] 모든 완료 기록 시도가 실패해도 Auth 삭제 성공 상태가 실패 응답으로 바뀌지 않는 테스트를 작성한다.

### 작업 2: 함수·운영 상태 구현

- [x] 완료 기록 재시도와 `completionPending` 응답을 구현한다.
- [x] Auth 삭제 전 실패와 Auth 삭제 후 완료 기록 실패를 분리한다.
- [x] 운영 상태에 오래 남은 준비 삭제 요청 수를 추가한다.
- [x] 운영자가 권한 있는 SQL Editor에서 완료 기록을 복구하는 절차를 Runbook에 기록한다.

### 작업 3: 검토와 검증

- [x] 독립 QA 에이전트가 비가역 작업의 상태 전이를 검토한다.
- [x] Edge Function 검사·테스트와 보안 검사를 실행한다. 로컬 Docker 부재로 DB 테스트는 GitHub CI에서 검증한다.
