# Talk후감 출시용 정책 · 문의 화면 계획

## 공개 화면과 진입점

| 화면 | 경로 | 사용자에게 필요한 이유 | 진입점 |
| --- | --- | --- | --- |
| 이용약관 | `/legal/terms` | 서비스 사용 규칙을 확인 | 로그인 하단, 설정, 동의 화면 |
| 개인정보처리방침 | `/legal/privacy` | 수집 정보와 처리 목적을 확인 | 로그인 하단, 설정, 동의 화면 |
| 서비스 이용 동의 | `/legal-consent` | 가입 뒤 서비스 진입 전 필수 약관 동의 | 로그인 콜백 뒤, 동의 버전이 없을 때 |
| 문의하기 | `/contact` | 오류·권리 행사·일반 문의 접수 | 설정 → 서비스 정보 |

필수 동의는 이용약관과 개인정보처리방침 두 항목뿐이다. 마케팅 동의는 Phase 1에 수집하지 않는다.

## 동의 기록 원칙

- `user_legal_consents`에 정책 종류, 버전, 동의 시각을 함께 보관한다.
- 같은 버전의 중복 저장은 허용하지 않는다.
- 정책 버전이 변경되면 새 버전 동의를 아직 기록하지 않은 사용자만 다시 동의 화면으로 보낸다.
- 브라우저가 테이블에 직접 쓰지 않고 `record_required_legal_consents` RPC만 실행한다.

## 외부 서비스 표기 범위

개인정보처리방침에는 사용자가 이해할 수 있는 **역할만** 적는다.

| 서비스 | 공개 문서에 적을 역할 | 공개하지 않을 운영 정보 |
| --- | --- | --- |
| Supabase | 로그인 세션, 데이터베이스 접근 제어, 서비스 데이터 저장 | 프로젝트 URL, 키, RLS 세부 규칙 |
| Mux | 사용자가 올린 영상의 업로드·변환·재생 | Access Token, signing key, webhook secret |
| 카카오·Google·Naver | 소셜 로그인 시 계정 식별 정보 제공 | OAuth client secret, callback 검증값 |
| Kakao Book Search | 도서 검색어에 맞는 도서 정보 제공 | REST API 키, 호출 제한 설정 |

처리자·국외 이전·보존 기간은 실제 운영 계약과 서비스 구조를 확정한 뒤 정확히 기재한다. 추측한 국가, 리전, 보안 설정을 사용자 문서에 쓰지 않는다.

## 공개 전 반드시 확정할 값

| 값 | 사용 위치 | 설정 위치 |
| --- | --- | --- |
| 운영자 또는 개인정보 보호책임자 표기 | 개인정보처리방침 | 정책 문서 본문 |
| 문의 이메일 | 문의하기, 개인정보처리방침 | Vercel `VITE_SUPPORT_EMAIL`, `apps/web/.env.local` |
| 시행일과 정책 버전 | 이용약관·개인정보처리방침·동의 기록 | `entities/legal/legalDocument.ts` |
| 개인정보 보유·이용 기간 | 개인정보처리방침 | 정책 문서 본문과 삭제 작업 정책 |
| 처리위탁·국외 이전 고지 필요 여부 | 개인정보처리방침 | 실제 Supabase·Mux 운영 조건 확인 뒤 법률 검토 |

## 출시 판단

현재 화면과 동의 기록 기능은 구현 대상이다. 다만 운영자 정보, 공개 문의 이메일, 실제 보유 기간 및 처리위탁·국외 이전 고지는 임의로 확정할 수 없다. 이 네 항목을 채우고 정책 문구를 법률 검토한 뒤에만 공개 출시한다.
