# 영상 보관함 썸네일 권한 최적화 계획

**목표:** 영상 보관함 진입 시 준비 완료 영상마다 재생 권한을 발급하던 요청을, 화면 단위의 썸네일 전용 권한 요청 한 번으로 줄인다.

## 원인

1. 기존 갤러리 카드는 각각 `mux-playback-token`을 호출했다.
2. 이 요청은 썸네일뿐 아니라 실제 영상 재생용 권한까지 함께 만들었다.
3. 영상 수가 늘수록 첫 화면 진입의 네트워크 요청과 Mux 서명 비용이 같이 늘었다.

## 범위

1. `mux-thumbnail-tokens` Edge Function을 추가한다.
2. 이 함수는 현재 사용자가 RLS로 읽을 수 있는 준비 완료 영상의 **썸네일 전용** 토큰만 최대 50개까지 발급한다.
3. 영상 보관함은 준비 완료 영상 식별자를 한 번에 요청하고, 카드에는 썸네일만 전달한다.
4. 실제 재생 토큰은 사용자가 특정 영상을 열 때 기존 `mux-playback-token`으로만 발급한다.
5. 카드 수와 무관하게 일괄 요청이 한 번만 나가는지 단위·E2E로 확인한다.

## 완료 기준

- 준비 완료 영상 여러 개를 표시해도 보관함 진입 시 재생 토큰 요청은 발생하지 않는다.
- 썸네일 권한 요청은 목록 단위로 한 번만 발생한다.
- 썸네일을 받지 못해도 준비 완료 카드는 열 수 있고, 상세 화면에서 기존 재생 권한 흐름을 사용한다.
- 새 Edge Function은 배포 후 기존 Mux 서명 비밀값만으로 동작한다. 새 Secret은 필요 없다.
