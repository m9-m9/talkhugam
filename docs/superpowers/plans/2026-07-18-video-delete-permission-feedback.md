# 영상 삭제 권한과 실패 복구 구현 계획

## 목적

영상 재생 화면에서 서버의 `delete_video_post` 권한 규칙과 동일하게, 작성자 또는 독서방 방장에게만 삭제 제어를 제공합니다. 삭제 요청이 실패하면 사용자가 원인을 추측하지 않도록 오류와 재시도 제어를 표시합니다.

## 범위

1. 현재 독서방 멤버의 역할과 영상 작성자 식별자를 도메인 경계에서 비교해 삭제 가능 여부를 계산한다.
2. 삭제 가능 사용자에게만 삭제 CTA를 렌더링한다.
3. 삭제 실패 시 오류 안내와 재시도를 제공하고, 성공 시 기존처럼 영상 목록을 무효화한 뒤 보관함으로 돌아간다.
4. repository·권한 mapper·화면 상호작용을 각각 테스트한다.

## 권한 근거

`public.delete_video_post(uuid)`는 이미 작성자 또는 활성 방장만 허용한다. 이번 작업은 이 서버 규칙을 바꾸지 않고, 클라이언트가 같은 정보를 조회해 잘못된 CTA를 예방하는 UX 보완이다. 서버 RPC는 최종 권한 경계로 계속 유지한다.

## 완료 기준

- 일반 멤버에게 삭제 버튼이 보이지 않는다.
- 작성자와 방장은 삭제 버튼을 볼 수 있다.
- 삭제 실패는 `role=alert` 문구와 재시도 버튼으로 복구할 수 있다.
- 성공 후 영상 보관함 cache invalidation과 화면 이동이 유지된다.
- 관련 Vitest, format, lint, typecheck, JSDoc 검사, build, Playwright를 실행한다.
